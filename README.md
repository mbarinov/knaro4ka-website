# Knara Sobchak — Next.js

Самостоятельный перенос [исходного сайта](https://gracious-raccoon-218479.framer.app/) из Framer. Next.js **16.3.4**, App Router, TypeScript, React. Версия Next.js проверена по npm dist-tag `latest` 7 сентября 2026 года. Сборка проверена на Node.js 24.13.0.

Перенесены `/`, `/about`, `/vocao`, `/cycle-aura` и собственная страница 404. Все изображения, видео, текстура, иконки и используемые начертания шрифтов находятся в `public/`. Во время работы сайт не загружает ресурсы, код или данные из Framer. Классы с префиксом `framer-` сохранены как обычные CSS-селекторы для точного соответствия макету.

## Запуск

Нужен Node.js 24 и npm. Из корня проекта:

```bash
npm ci
npm run dev
```

Открыть http://127.0.0.1:3000. Редактирование файлов обновляет страницу автоматически.

Проверка и production-сборка:

```bash
npm run check
npm run start
```

`check` последовательно запускает TypeScript, ESLint и `next build`. Перед `start` нужно остановить dev-сервер на том же порту либо передать другой порт: `npm run start -- --port 3001`.

## Деплой на Vercel

1. Добавить проект в свой Git-репозиторий вместе с `package-lock.json` и `public/`.
2. В Vercel создать проект и импортировать этот репозиторий. Если сайт лежит в подпапке репозитория, выбрать её как Root Directory.
3. Использовать Framework Preset **Next.js**, Build Command `npm run build`. Output Directory оставить настройкой Next.js по умолчанию.
4. Добавить `SITE_URL` с окончательным адресом сайта, например `https://your-domain.com`. Эта переменная определяет canonical, sitemap и абсолютные OG-ссылки. Без неё используется `VERCEL_PROJECT_PRODUCTION_URL`, а локально — `http://localhost:3000`. После изменения адреса нужна новая сборка.
5. Нажать Deploy. Затем при необходимости подключить свой домен в настройках проекта.

Дополнительный backend, база данных, CMS и API-ключи не требуются. Настройки Next.js определяются Vercel автоматически: [официальная инструкция](https://vercel.com/docs/frameworks/full-stack/nextjs), [варианты деплоя](https://vercel.com/docs/deployments).

**Деплой в рамках переноса не выполнялся.**

## Где менять сайт

- `src/components/pages/` — содержание пяти страниц.
- `src/components/site-components.tsx` — навигация, контакты, нижний логотип и список специализаций.
- `src/components/interactions/` — появление блоков, ленты, наклон карточек, параллакс и плавная прокрутка.
- `src/components/page-transition.tsx` — переходы App Router с исходной маской.
- `src/app/source-layout.css` — исходные сетки, размеры и адаптивные правила; `globals.css` — общие компоненты и интерактивные состояния.
- `src/app/fonts.css` — локальные шрифты; `src/asset-map.json` — соответствие исходных URL локальным ресурсам.
- `src/app/layout.tsx` — title, description, favicon, Open Graph и Twitter metadata.

Визуальный редактор Framer не переносится: содержание редактируется в этих файлах. В исходнике не обнаружены рабочие формы, CMS-коллекции или закрытые интеграции.

## Сохранённые особенности оригинала

- В About есть черновые карточки `RFJF`, повторяющийся текст и опечатки. Они перенесены без редактирования.
- Title, description и OG-картинка всё ещё относятся к шаблону **Sienna Vanghn**. Они сохранены по условию переноса SEO; перед публикацией их можно заменить в `layout.tsx`.
- Футер Cycle Aura расположен внутри длинного кейса и сохраняет фиксированную ширину 1200 px даже на телефоне. Поэтому его большой текст обрезается на узком экране, как в оригинале. Переполнения всей страницы по горизонтали нет.
- Серые геометрические карточки в движущихся лентах присутствуют и в оригинале.

Исправлены три неработавшие ссылки исходника: email теперь ведёт на отображаемый `knarasobchak@gmail.com`; Contact в кейсах ведёт к их контактному блоку; Go to website открывает Cycle Aura без ошибочного атрибута скачивания.

## Проверка переноса

Результаты, методика и ограничения: [design-qa.md](design-qa.md).

Локальные доказательства сохранены в `evidence/`: исходные и итоговые снимки, координаты элементов, наложения и отчёты. Эта папка не нужна для сборки и исключена из Git и загрузки на Vercel.

Для повторного анализа уже снятых кадров нужны Python, Pillow, requests и beautifulsoup4:

```bash
python3 -m venv .venv-qa
.venv-qa/bin/pip install Pillow requests beautifulsoup4
.venv-qa/bin/python scripts/compare-visuals.py
.venv-qa/bin/python scripts/verify-runtime.py http://127.0.0.1:3000
```

Браузерные снимки создаются отдельно при одинаковых размерах окна, масштабе 100%, состоянии загрузки и прокрутке. `scripts/generate-migration.py` и `collect-source-assets.py` — вспомогательные инструменты первоначального переноса, а не часть сборки; для обычного редактирования сайта они не нужны.

## Производительность и обновление ассетов

PNG/WebP используют оптимизатор Next.js и адаптивные размеры; компактные AVIF и SVG сохраняются в исходном виде. Подробности и результаты проверки — в `PERFORMANCE-AUDIT.md`.

Файлы `/assets/<12 hex символов>.<расширение>` кешируются на год с `immutable`. **Нельзя заменять их содержимое по прежнему URL:** создавайте новое имя из первых 12 символов SHA-256 содержимого и обновляйте ссылки в коде и `src/asset-map.json`, если там есть соответствующая запись. Для прежних импортированных файлов действует то же правило нового имени при изменении. `noise.png` и favicon под это правило кеширования не попадают. Генератор первоначального переноса не запускать поверх отредактированного сайта.

Видео `efbed6ee263d.mp4` — faststart-копия исходного `42e209336fc2.mp4` без перекодирования; `669855084faa.webp` — poster первого кадра. Оригинал сохранён. Для пересоздания нужны FFmpeg (`-map 0 -c copy -movflags +faststart`) и Sharp; имена новых результатов должны вычисляться из их содержимого.

После `npm run check` запустите production-сервер и выполните:

```bash
node --test scripts/interactions.test.mjs
node scripts/check-performance.mjs http://127.0.0.1:3001
.venv-qa/bin/python scripts/verify-runtime.py http://127.0.0.1:3001
```

Первая проверка сверяет адаптивный hero, кеш, размер оптимизированной картинки, состав JS и структуру MP4. Это не замер LCP/INP/CLS. Результаты сохраняются в игнорируемой Git папке `evidence/performance/`.

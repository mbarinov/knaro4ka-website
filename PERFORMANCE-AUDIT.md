## База уже хорошая

- Все основные маршруты статически пререндерены. Нет обнаруженной необходимости вычислять страницы на каждый запрос или ждать внешние API.
- Контент страниц остаётся Server Components; клиентские обёртки с `children` сами по себе не превращают всё дерево в клиентский код.

- Production JS/CSS имеют годовой immutable-кеш. HTML и текстовые ассеты действительно отдаются с gzip при соответствующем GET-запросе.
- Изображения имеют размеры; большинство некритичных изображений загружается лениво.

- Reveal, Ticker, SmoothScroll и ParallaxHeading учитывают reduced motion; эффекты имеют cleanup.

## P1 — включить адаптивную оптимизацию растровых изображений

**Подтверждено.** `unoptimized` есть во всех 34 использованиях `Image`. На проверенных страницах в DOM отсутствуют `srcset` и `sizes`, хотя `sizes` записаны в JSX. Следовательно, они сейчас не помогают браузеру выбрать меньший вариант.

Примеры: `src/components/pages/home.tsx:398`, `src/components/pages/about.tsx:168`, `src/components/pages/vocao.tsx:169`, `src/components/pages/cycle-aura.tsx:187`.

Проверка реального endpoint:

```text
GET /_next/image?url=%2Fassets%2Fb77835e7e6a3.png&w=640&q=75
Accept: image/webp
→ 200, image/webp, 31 676 байт
```

| Файл | Исходник, КБ | Тестовый WebP q75, КБ | Ширина теста | Сокращение |
|---|---:|---:|---:|---:|
| `b77835e7e6a3.png` — Cycle Aura, центр | 399,8 | 31,7 | 640 px | 92% |
| `257e6f8bfacb.png` — Cycle Aura, первый экран | 401,5 | 50,4 | 640 px | 87% |
| `93319df78041.png` — Cycle Aura, первый экран | 265,3 | 30,6 | 640 px | 88% |
| `f6c773baa9fc.png` — About | 1012,9 | 44,6 | 640 px | 96% |
| `433527337bf7.png` — главная, тикер | 281,1 | 21,5 | 400 px | 92% |
| `04aee89f50b2.png` — Vocao | 981,5 | 106,0 | 640 px | 89% |
| `0751622d657b.png` — Cycle Aura | 772,2 | 45,0 | 640 px | 94% |

Кроме первого endpoint, таблица получена локальным Sharp. Это сравнение файлов, а не обещание такого же улучшения LCP. Конкретный браузер может выбрать 750/1080 px или другой размер по DPR. Качество мелкого текста на мокапах после сжатия ещё нужно визуально проверить.

**Рекомендация:** убрать `unoptimized` у подходящих растровых изображений и уточнить `sizes` по реальной CSS-ширине. Например, обложки главной сейчас описаны как `100vw`, хотя в проверенном viewport 651 px картинка была шириной около 356 px. После включения оптимизатора завышенный `sizes` приведёт к избыточному варианту.

Для фиксированных изображений тикера 200 CSS px текущие 200 px в `sizes` логичны. Не требуется прогонять маленькие SVG через растровый оптимизатор. Уже компактные AVIF стоит сравнить с выходом оптимизатора: повторное кодирование не гарантирует выигрыш.

## P1 — убрать lazy-loading у изображений первого экрана

**Подтверждено:** центральная картинка `/assets/b77835e7e6a3.png` на Cycle Aura видна в desktop viewport 1439×900: верх около 462 px, ширина около 340 px. При этом `loading="lazy"`. Исходный размер — 1608×2154.

В мобильном viewport 390×844 виден другой набор: первая карточка начинается при x≈16, центральная — x≈316, третья — за правой границей. Верх карточек около 495 px. Поэтому универсально приоритизировать только центральную картинку недостаточно: основной кандидат на мобильном может отличаться.

**Рекомендация:** для реально видимых hero-изображений использовать `loading="eager"`; `fetchPriority="high"` назначать ограниченно, после определения кандидата для соответствующего breakpoint. Не делать все картинки страницы eager.

В `cycle-aura.tsx` те же картинки есть в двух responsive-группах: центральная на строках 187 и 2062. Одна группа скрыта CSS. Слепая замена свойств у обеих групп может вызвать ненужные ранние запросы; лучше объединить адаптивный hero либо управлять ранней загрузкой с учётом media. Повторение URL не означает удвоение сетевого трафика.

`preload` нужен только если есть основание начинать запрос ещё из head. В Next.js 16 `priority` устарел; документация не рекомендует совмещать `preload` с `loading`/`fetchPriority`. [Image: загрузка и предварительная загрузка](https://nextjs.org/docs/app/api-reference/components/image#loading).

Проверить аналогично первый экран About и главной; у About портрет весит больше мегабайта. На Vocao в проверенном мобильном первом экране изображений не было, поэтому глобальный eager для его галереи не обоснован.

## P2 — кешировать версионированные ассеты

**Подтверждено HTTP-запросом в production:** PNG и WOFF2 из `/assets/` возвращают `Cache-Control: public, max-age=0`. Это допускает хранение, но заставляет перепроверять свежесть перед повторным использованием; не обязательно скачивать весь файл заново. В отличие от них `/_next/static/` уже использует `max-age=31536000, immutable`.

**Рекомендация:** для ассетов с гарантированным новым именем при каждом изменении установить длительный immutable-кеш на сервере/CDN. Названия выглядят как хеши, но нужно подтвердить правило их обновления. Не применять годовой immutable вслепую ко всему `/assets/`: там есть стабильное имя `noise.png`, а существующий процесс может перезаписывать файлы.

Проверенный endpoint оптимизации изображений уже отдаёт `max-age=14400, must-revalidate`. После включения оптимизатора перепроверить фактические заголовки и холодный/прогретый image-cache в целевой среде. Локальные заголовки ещё не доказывают поведение публичного CDN.

## P2 — облегчить и правильно подготовить видео

**Подтверждено:** `src/components/pages/vocao.tsx:401`, MP4 19,3 МБ, `preload="metadata"`, без poster и autoplay. На мобильном видео начинается ниже первого экрана, y≈928 px.

Разбор контейнера показал `mdat` с offset 40 и `moov` с offset **19 243 225**, почти в конце. Браузеру для metadata может понадобиться дополнительный запрос к хвосту файла. Это не доказывает загрузку всех 19,3 МБ.

**Рекомендация:** remux с `faststart`, перенеся `moov` в начало без перекодирования. Затем отдельно подобрать разрешение/битрейт по реальному размеру видео и визуальному качеству. Добавить лёгкий poster. Для ролика ниже первого экрана рассмотреть `preload="none"` или назначение источника при приближении к viewport; проверить задержку первого запуска как обратную сторону экономии.

Критерий: без нажатия Play нет полной загрузки ролика; старт воспроизведения не ухудшился. [Поведение video и preload](https://web.dev/articles/video-and-source-tags).

## P2 — сделать загрузку шрифтов предсказуемой

**Подтверждено:** восемь `@font-face` в `src/app/fonts.css`, локальные WOFF2, ручное подключение через общий CSS. Для Geist Mono 700 на строке 30 нет `font-display`; у остальных объявлений есть swap. В HTML нет явного preload шрифтов.

**Рекомендация:** рассмотреть `next/font/local`, сохранить семейства и начертания, настроить fallback и preload только критичных шрифтов. Для первого экрана наиболее очевидные кандидаты — Gambarino 400 (16,7 КБ) и Geist Mono 500 (30,5 КБ). Проверить реальное использование, прежде чем загружать оба на всех маршрутах.

Не считать, что все восемь шрифтов скачиваются всегда: наличие `@font-face` этого не доказывает. CLS от подмены шрифта также пока не измерен. Нужны холодная загрузка, проверка переносов строк и профиль layout shifts.

## P2 — убрать ненужные зависимости и работу эффектов

**Подтверждено:** `src/components/interactions.tsx` статически импортирует Lenis и react-parallax-tilt. Production-чанк, содержащий обе библиотеки и код эффектов, — 45,7 КБ / 12,4 КБ gzip; он подключается ко всем четырём страницам. Нельзя приписывать весь размер чанка одной библиотеке.

SmoothScroll не создаёт Lenis на `/vocao` и `/cycle-aura`, но код библиотеки туда всё равно поставляется. TiltCard нужен для обложек главной, а его библиотека оказывается в общем чанке.

**Рекомендация:** разделить SmoothScroll, TiltCard и прочие эффекты на модули; загружать Lenis и tilt только там, где они используются. Для tilt учитывать fine pointer и reduced motion до инициализации библиотеки. Приоритет умеренный: даже весь общий чанк эффектов меньше одного исходного PNG.

Ticker работает бесконечно и не проверяет видимость секции. SmoothScroll использует `autoRaf`; ParallaxHeading пишет transform на scroll. Reveal запускает анимацию при mount без проверки попадания секции в экран. Предлагается останавливать эффекты вне viewport, объединять необходимые обновления с кадром и сравнить с нативным скроллом на слабом устройстве. Бесконечная анимация не равна постоянной дорогой перерисовке: compositor может выполнять transform эффективно. Просадки FPS и плохой INP пока не доказаны.

## P2/P3 — сократить задержку визуального перехода

`src/app/globals.css:272` задаёт односекундный переход с анимацией mask-gradient. Он может делать даже готовую страницу субъективно медленной; стоимость отрисовки требует Performance trace.

Для цели «максимально быстро» стоит сравнить короткий переход 150–250 мс с текущим и отключением перехода. Это изменение ощущения и дизайна, а не гарантированная экономия секунды сетевого LCP. Reveal также использует длительность 1 с и задержки 200–300 мс; не стоит прятать уже готовый важный контент после hydration без причины.

## P3 — разделить общий CSS, не начинать с полной переделки

Все страницы получают общий stylesheet с правилами разных Framer-страниц. Предлагается отделить общую типографику/навигацию от стилей home, about и кейсов и удалить доказанно неиспользуемые правила.

Потенциальная польза: меньше разбора CSS, проще каскад. Но передавается всего около 14,1 КБ gzip; это не первый источник большой сетевой экономии. Нет CSS Coverage, поэтому процент неиспользуемых правил неизвестен. Не удалять правила по совпадению имён классов без проверки responsive-состояний.

Наблюдаемый DOM тоже не экстремален: около 207 элементов на About, 254 на Vocao и 276 на Cycle Aura в production-проверке. Большое число строк JSX не означает огромный DOM или эквивалентный клиентский bundle.

## P3 — пересмотреть переходы в кейсы, если допустимо по UX

`src/components/pages/home.tsx:383` и `:474`: ссылки на внутренние кейсы — `<a target="_blank">`. Это намеренно открывает новый документ и не использует обычный клиентский переход Next Link.

Если новая вкладка не принципиальна, `Link` в той же вкладке даст возможность клиентской навигации и prefetch. Это прежде всего решение о поведении сайта; не менять его автоматически ради рейтинга. Prefetch может увеличить фоновый трафик, поэтому его пользу нужно проверить.

1. Снять повторяемый baseline production в Lighthouse/DevTools: минимум три холодных прогона каждого маршрута, mobile/desktop, одинаковый профиль сети и CPU; отдельно тёплая навигация. Зафиксировать LCP-элемент, waterfall, байты и long tasks.

3. Настроить кеширование версионированных файлов; проверить повторное посещение и обновление изменённых ассетов на реальном хостинге.
4. Подготовить faststart/poster видео и загрузку критичных шрифтов. Сравнить старт ролика и CLS.
5. Разделить библиотеки эффектов, проверить скролл и переходы на устройстве; затем оценивать пользу разделения CSS.
6. Повторить те же измерения после изменений, сохранить отчёты и добавить контроль регрессий. Для реальных посетителей собирать LCP/INP/CLS отдельно по маршрутам и mobile/desktop, если подключается соответствующая аналитика.

Ориентиры Core Web Vitals: **LCP ≤2,5 с, INP ≤200 мс, CLS ≤0,1 на 75-м перцентиле**. Lighthouse не заменяет полевой INP; в обычном прогоне загрузки он использует TBT как вспомогательный индикатор. Это цели, а не текущие измерения сайта. [Определения и пороги Web Vitals](https://web.dev/articles/vitals).

Наиболее обоснованное первое изменение — изображения и их раннее обнаружение: экономия байтов подтверждена реальным endpoint, предупреждение соответствует атрибутам и положению изображения. [Рекомендации по диагностике LCP](https://web.dev/articles/optimize-lcp).

## Результат реализации

Первый этап выполнен с сохранением размеров, шрифтов, текстов, длительностей анимаций и открытия кейсов в новой вкладке. Деплой и внешняя аналитика не выполнялись.

### Что изменено

- PNG/WebP используют штатный Next Image с `srcset` и уточнёнными `sizes`. AVIF и SVG сохранены без перекодирования. В частности, обложки главной имеют `sizes="356px"`, а портрет About теперь точно соответствует CSS-ширине 29% на десктопе.
- Hero Cycle Aura объединён в одну серверную responsive-галерею. На странице 13 изображений вместо 16, три hero-картинки загружаются eager. На мобильном сохранена горизонтальная прокрутка и карточки 284×382 px. На главной eager используется для верхнего тикера, на About — для портрета.
- Центральному мокапу Cycle Aura назначено качество 85 после визуального сравнения мелкого текста; остальные оптимизированные изображения используют 75. Высокий сетевой приоритет не назначался всем картинкам.
- Кеш на год с immutable применяется только к именам из 12 hex-символов и предусмотренных расширений. `noise.png` и favicon исключены. Правило нового имени при изменении содержимого добавлено в README.
- Через React DOM `preload` подключены только Gambarino 400 и Geist Mono 500. В итоговом HTML ровно два font preload. Geist Mono 700 получил `font-display: swap`.
- Добавлены faststart MP4 `efbed6ee263d.mp4` и poster `669855084faa.webp`. Исходное видео сохранено. Потоки не перекодировались; SHA-256 сжатых видео/аудиопотоков до и после совпадает. Poster занимает 37 740 байт. Размер нового MP4 — 19 290 946 байт: faststart меняет порядок контейнера, а не сокращает видеопоток.
- Клиентские эффекты разделены на прямые импорты. Lenis загружается динамически только для `/` и `/about`, tilt — при использовании карточек и разрешённой анимации. Тикеры приостанавливаются вне viewport и при скрытой вкладке, сохраняя фазу. Параллакс перестаёт обновляться вне экрана. Длительности Reveal и переходов не изменены.

### Доказательства и оставшиеся ограничения

В `evidence/performance/before/` и `after/` сохранены снимки viewport, геометрия и сводки ресурсов. Первые быстрые снимки во время Reveal были заменены стабильными состояниями перед сравнением. Исходная production-сборка запускалась отдельно из временной папки, финальная — из проекта. Существующий dev-сервер не останавливался.

Дополнительные файлы: `layout-comparison.json`, `video-stream-hashes.json`, `runtime-checks.json`, `image-quality.png`, `quality-75-85.png`. Команды повторных проверок добавлены в README.

LCP/INP/CLS, Lighthouse, CPU/4G-профиль и реальные показатели CDN Vercel не измерены: инструмент Browser не предоставляет Performance API/trace.
